# UI Product Standards

Read when designing screens, choosing components, or judging whether a UI is ready to ship.

## Product Bar
Build interfaces that feel like real production software, not prototypes. Optimize for: consistent layout, clear hierarchy, predictable UX, strong performance, scalable composition. Keep the interface calm, premium, structured, intentional.

## Design Direction
Generous whitespace, steady layout rhythm. Clean, readable, deliberate typography. Refined color with restraint. Modern minimalism over visual noise.

Avoid: cluttered layouts, inconsistent spacing, generic AI-looking compositions.

### Design Skills
`design-taste-frontend` (researched art direction + no-slop inspector loop), `hallmark` (designed-not-generated pages), `ui-ux-pro-max` (styles/palettes/font-pairings library), `emil-design-eng` (UI polish philosophy), `make-interfaces-feel-better` (micro-interaction detail pass), `nothing-design` (only when the user says Nothing style).

## Component Strategy

### Skills
`shadcn` (registries, MCP), `ui-ux-pro-max` (79 styles, 192 palettes, 74 font pairings), `design-taste-frontend` (anti-slop direction + real-browser inspector loop), `hallmark` (designed pages), `awwwards`/`jury` (award-caliber build / scored review), `react-expert` (React 18+, Server Components, hooks), `solidjs-expert` (SolidJS only when user explicitly requests).

### Selection Order
1. **Magic UI MCP** first when available.
2. **shadcn/ui** (React) or **shadcn-solid** (SolidJS) before custom components.
3. **MapCN** (`references/maps.md`) for any map/location component.
4. Invoke `design-taste-frontend` or `hallmark` for design-heavy work.
5. Inspect `skills/` directory first; reuse skills over reimplementing.
6. Inspect existing project components before creating something new.
7. Tailwind utilities where practical; composition over custom overrides.

**React is the priority. SolidJS is secondary — only when user explicitly requests.**

## Interaction & Motion
Subtle transitions, clear hover states, responsive feedback. Animation in service of clarity, not decoration. No heavy/distracting motion. Prioritize performance. Use [Haptics Reference](https://haptics.lochie.me/) when useful. Always use **Boneyard** (https://github.com/0xGF/boneyard) — references there, use everywhere.

## Quality Targets
Polish level of Linear, Vercel, Stripe Dashboard, Supabase, Railway, Appwrite, Notion — without copying them directly.

## UI Rules
- Mobile responsive by default.
- Dark + light mode unless task clearly does not need both.
- Accessible components (a11y-first).
- Predictable spacing scale, consistent border radii.
- No emojis in UI unless user explicitly asks.

## Final Review (before finishing)
Confirm: clean whitespace, consistent spacing, readable typography, strong visual hierarchy, balanced layout, responsive behavior.

### Final Review Skills
`make-interfaces-feel-better` (alignment/spacing/micro-interaction polish), `web-design-guidelines` (a11y/UX/anti-pattern audit), `jury` (scored design critique), `design-taste-frontend` (if the result looks generic or AI-made — rerun its look-and-fix loop).

If the result still looks generic or autogenerated, redesign it.
